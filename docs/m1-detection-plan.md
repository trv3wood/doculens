# M1 自动找边实施计划

分支 `codex/m1-detection`，从 M0 验收提交 `0c47721` 开始。工作范围为 `src/workers/`、找边评估脚本及相应用例。与界面分支保持 Worker 消息结构、坐标含义、日志和现有回退行为兼容。若确需改变接口，先在两条分支约定迁移方式。

## 实施顺序

1. 复跑 [M0 质量基线](./m0-quality.md)。固定 24 张 SmartDoc 样本、原始标注及评价口径。基线为检出 10/24，检出样本平均 IoU 98.30%，漏检计 0 后整体平均 IoU 40.96%。
2. 为漏检加可控的离线诊断，区分候选生成、轮廓拟合、边缘证据、纸面与背景对比度和候选歧义。为每类典型失败保留叠图和拒绝原因。
3. 按失败分布逐项尝试候选生成和评分改进，每次记录检出、整体 IoU、误裁和耗时变化。保留手动调角及整图回退，并用无完整纸边的样本检查误裁。
4. 冻结候选算法后，在未参与调参的独立文档上复验。不把同一文档的不同帧分入调参与独立验收两侧。按文档保存预测、真值、误差及误裁说明。
5. 跑类型检查、现有浏览器回归和原界面的 MApp 真机快速回归。合并后再参与集成候选包的正式验收。

## 验收口径

- 固定 24 张回归集的工程目标为至少检出 16/24，整体平均 IoU 高于 40.96%。逐张检查新增检测，确认无明显正文误裁。独立集单列结果。
- 同时报告检出率、整体及检出样本 IoU、归一化角点误差、误裁、自动找边耗时。缺失预测记入漏检，整体 IoU 中记 0。
- 仍能正常处理 12MP JPEG 并导出三种格式。桌面和真机结果分别记录。开发快速回归跑 5 轮，记录 P50、最慢一轮和失败次数；M1 正式性能验收沿用规格中的至少 10 轮。
