# M1 跨背景找边评估

从 SmartDoc v2.0.0 原始归档选取 30 份文档、5 种实拍背景。每个文档和背景组合按帧序号排序，在四分之一、中间和四分之三位置各取一帧，共 450 帧。采用数据作者的原始标注，漏检按 IoU 0 计。数据来源与署名见 [M0 质量基线](m0-quality.md)。

文档编号 001–003 用于开发（270 帧），004–005 用于对照验证（180 帧）。两个分组按文档互斥。同一序列的三帧具有相关性。此前 M0/M1 回归已使用部分验证文档，结果只反映跨背景表现。最终 5% 门槛参考了开发集小纸张面积，并使用原有的 24 张正文负例筛查误裁。

| 背景（每种 90 帧） | 4be18f5 检出 | 本轮检出 | 整体 IoU 前 → 后 |
|---|---:|---:|---:|
| 01 | 88 | 90 | 96.00% → 98.17% |
| 02 | 64 | 87 | 69.35% → 93.96% |
| 03 | 77 | 90 | 84.37% → 98.58% |
| 04 | 72 | 73 | 77.68% → 78.75% |
| 05 | 1 | 1 | 0.93% → 0.93% |

开发集从 181/270 提高到 205/270，验证组从 121/180 提高到 136/180。总检出从 302/450 提高到 341/450，整体平均 IoU 从 65.66% 提高到 74.08%。仅对有预测的帧计算，平均 IoU 从 97.84% 变为 97.76%，平均归一化角点误差从 0.225% 变为 0.226%。原有 302 个预测的坐标逐一相同。新增 39 个预测的平均 IoU 为 97.10%，最低 94.16%。原有预测中最低为背景 05 的 magazine005，第 22 帧，IoU 83.73%。[逐帧真值、两个版本的预测及误差](m1-smartdoc-frames.jsonl)

远拍样本有些整页仅占照片的 5%–8%。直接降低所有轮次的面积门槛曾导致资料表内部的矩形抢先被接受。最终只在原算法未找到候选时尝试 600 和 360 像素预览，分别使用 10/30、5/15 的 Canny 阈值及 5% 面积下限，沿用四边证据及歧义检查。试验的 4.5% 门槛在正文裁片上造成一次误裁。最终 24 张正文负例均保留整图。

背景 05 的桌面物品遮住纸边，仍漏检 89/90；背景 04 漏检 17/90。该轮收益主要来自完整但较小的纸张。

## 复跑

使用 M0 文档中的同一份帧归档，在仓库根目录执行。每个背景报告包含质量 JSON、真值叠图与扫描预览。

```sh
python3 scripts/extract-m0-smartdoc.py .cache/m0/frames.tar.gz .cache/m1/expanded --expanded
bun run build:worker
for split in development validation; do
  for dir in .cache/m1/expanded/"$split"/background*; do
    node scripts/evaluate-m0-quality.mjs "$dir" ".cache/m1/report/$split/${dir##*/}" || exit 1
  done
done
```

## 桌面性能

同一张 12MP JPEG 在 Chrome 上每版各跑 5 轮，均成功导出 JPEG、PNG、PDF。自动找边 P50 从 244.6 ms 升至 342.2 ms，最慢一轮从 249.0 ms 升至 346.2 ms。两次额外搜索会增加走到回退路径时的耗时。此次未测手机。
