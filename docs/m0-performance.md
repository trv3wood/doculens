## 采样口径

每次关闭并重新打开沙箱，等待自动初始化，选同一份 4000×3000 JPEG，完成扫描、切换 PDF 和系统保存。重新打开沙箱会重新创建 Worker；宿主进程和系统缓存可能继续保留。每项使用至少 10 次有效试验，P50 取中位数，P95 取最近秩。单次失败写入原始报告，失败次数以所有尝试为分母。

| 指标 | 起止点 |
|---|---|
| 首屏可选图 | 应用脚本入口到首次更新选图控件状态。该值不含宿主加载包、脚本依赖加载和屏幕绘制。 |
| 引擎就绪 | 应用脚本入口到 Worker 初始化返回且扫描客户端可用。 |
| WASM 初始化 | Worker 开始创建 OpenCV 模块到模块就绪。 |
| 原图预览 | 扫描操作开始到绘制原图及裁切预览。 |
| 自动找边 | Worker 的角点检测调用起止，包含该调用内部生成的灰度缩略图。 |
| 完整扫描 | 扫描操作开始到默认 JPEG 导出就绪，包含解码、Worker 回传和编码。 |
| PDF 准备 | 首次切换 PDF 到该产物就绪，包含可能尚未编码的 PNG。 |
| 系统保存 | 点击保存到宿主 SDK 返回，含授权和文件选择器交互。 |

内存使用可复现的分配下界。将 RGBA 消息复制进输入 Mat 时，原始传入 Buffer 与 Mat 像素区重叠。12MP 两块 RGBA 像素区共 96,000,000 字节（约 91.6 MiB），24MP 同口径为 192,000,000 字节（约 183.1 MiB）。这两个数值未计解码缓存、输出、Canvas、其他 Mat 和 WASM heap 的保留空间，无法推算系统物理内存峰值。

## 运行方式

使用 [MApp 检查清单](./m0-mapp-checklist.md)的真机准备步骤。在常规回归命令上追加：

- `--measurements 10` 记录 10 次 12MP 尝试，出现失败时保留失败记录并增加试验次数。若同一候选包已通过功能回归，可加 `--performance-only` 单独采样。
- 重复传入五个 `--continuous-fixture` 参数，在一次沙箱会话中处理五张独立文档。
- 传入 `--extended-fixture 'doculens-24mp, jpg'` 检查 6000×4000 JPEG 的扩展范围提示与扫描结果。可复用检查清单中的夹具生成命令，将尺寸改为 6000×4000。
- 对合并候选包完成三种格式落盘验证。性能试验生成的 PDF 保存到「我的 iPhone → Downloads」，使用运行时间戳和序号命名。每次运行在报告目录记录 `performance-attempts.json`、`performance-summary.json` 和诊断日志。
