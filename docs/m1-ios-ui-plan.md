# M1 iOS 风格界面实施计划

分支 `codex/m1-ios-ui`，从 M0 验收提交 `0c47721` 开始。工作范围为界面模板、样式、组件依赖、必要的 DOM 绑定和界面回归。保留 Worker 协议和诊断日志。调整 Appium 控件定位时同步脚本。

## 实施顺序

1. 在 LINUX DO iOS 宿主观察实际字号、留白、分组、主次操作、深浅色和安全区域。以宿主原生导航和工具栏为边界，设计 DocuLens 的导入、裁切及导出界面。
2. 做最小 Ionic Core iOS 模式原型，先试用分组列表、按钮和格式选择控件。选择能局部引入的组件，沿用现有宿主主题接入方式。记录依赖、包体差值和首屏影响。 [Ionic 列表控件](https://ionicframework.com/docs/api/item) · [Ionic 选择控件](https://ionicframework.com/docs/api/select)
3. 在完整打包前验证组件能随 ZIP 本地加载，并通过官方 packer 与真实 MApp 的首屏、主题切换、选择和保存。若组件依赖与宿主冲突，缩小组件使用范围，保留已通过验证的原生 HTML 控件。
4. 原型通过后逐步替换导入、扫描选项及导出区。保留原生系统选图、保存与授权流程，以及裁切画布和四角拖拽交互。优先让当前阶段的主要操作容易找到。
5. 回归窄屏、深浅色、触控、无障碍名称、处理中禁用状态、失败重试和 JPEG／PNG／PDF 实际落盘。集成后核对 Appium 回归定位。

## 验收口径

- 用浅色与深色真机截图核对视觉一致性。首屏能选图，扫描、调角、旋转和保存路径完整，主操作及状态信息清晰。
- 记录 ZIP 和主要资源体积对比，并通过官方打包校验。组件与样式随包交付，运行时无需 CDN。
- 保留三种格式导出、拒绝后重试、缓存复用和旋转后重新编码行为。真机回归保存到「我的 iPhone → Downloads」。
- 开发阶段使用 5 轮快速采样，记录 P50、最慢一轮和失败次数；与算法合并后，使用统一候选包完成 M1 正式真机与性能验收。
