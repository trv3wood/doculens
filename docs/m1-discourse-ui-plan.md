# M1 Discourse 风格界面实施计划

以已合入扫描增强的主线为基线，覆盖界面模板、样式、控件选型和交互回归。沿用 Worker 协议、裁切画布、诊断日志和系统选图、保存及授权流程。控件定位发生变化时同步更新 Appium 脚本。

## 实施顺序

1. 用 LINUX DO 宿主当前主题的浅色和深色真机截图作为视觉基准。参考论坛的按钮层级、表单间距和分组方式。沿用 SDK 主题读取和变更订阅，将可用主题值映射到背景、文字、边框、主操作、焦点以及裁切线。SDK 未提供的颜色以宿主截图为参考配置浅色和深色默认值。
2. 先做「选图 → 扫描 → 保存」原型。选图后显示文件名，以「生成扫描件」为主操作。扫描效果使用单选按钮组。将摩尔纹和模糊复原放入「高级增强」，开启模糊复原后显示类型选择。
3. 裁切工具靠近原图。宽屏并排显示原图和结果，窄屏先采用上下排列。结果旁突出「保存扫描件」，保留分享及原生格式选择器。就地显示处理中、失败及完成状态。
4. 常规控件使用原生 HTML 和本地样式。真机原型若需要自定义菜单或标签页，按需试用 Radix Primitives，通过 Preact 兼容层接入。验证打包、触控和键盘焦点后决定是否保留。 [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction) · [Preact 兼容层](https://preactjs.com/guide/v11/upgrade-guide/)

## 验收口径

- 在 LINUX DO 真机验证浅色、深色及主题切换。检查窄屏无横向溢出，主操作清晰，裁切点可触控拖动，键盘焦点和控件名称可辨认。
- 验证首屏选图、扫描、调角、旋转、更新后旧导出失效及失败重试。覆盖三种格式落盘、导出缓存复用和旋转后重新编码。iPhone 的落盘路径为「我的 iPhone → Downloads」。
- 记录 ZIP 和主要资源体积、首屏耗时变化，并验证官方打包。组件与样式随包交付，运行时无需 CDN。
- 开发阶段进行 5 轮快速采样，记录 P50、最慢一轮和失败次数。用统一候选包完成 M1 正式真机与性能验收。
